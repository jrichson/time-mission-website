## Notable Deviation (Auto-fixed)

**Plan-spec inline pattern**: `<script>window.TMPage.initCity({...})</script>` placed AFTER `<script defer src="page-widgets.js">` was caught by smoke tests as `Cannot read properties of undefined (reading 'initCity')`. **Root cause:** synchronous inline scripts execute during HTML parse, BEFORE deferred external scripts run.

**Fix (commit `7438289`):** Inverted to a config-stash pattern — `window.__TM_PAGE_INIT__` set inline first, consumed by `page-widgets.js`'s auto-init when it runs after parse. This mirrors the existing `window.__TM_DATA__` hand-off used by `SiteScripts.astro` + `js/locations.js`. `window.TMPage.initCity` / `window.TMPage.initIndex` retained as alternate API for non-deferred callers.

## Public API Surface

`window.TMPage` exposes exactly two methods (per RFC contract):

- `TMPage.initCity(config: { city: string; taglines: string[]; gamePopup?: boolean })` — registers `window.updateEyebrowLocation` internally
- `TMPage.initIndex(config: { taglines: string[]; heroVideo?: boolean; gamePopup?: boolean })` — registers a no-op `updateEyebrowLocation` stub

Plus the auto-init helper:

- `window.__TM_PAGE_INIT__ = { kind: 'city' | 'index', config: {...} }` — set inline before the deferred widgets script loads; consumed automatically.

## Index-Style "Strict Superset" Widgets

The index variant of several widgets had defensive improvements over the city variant. The plan chose to ship the strict-superset version to all pages (visual parity preserved; only edge-case robustness improved):

- `mini-faq` with `aria-expanded` toggling
- `smoothSlide` with backward-from-zero handling
- `smoothScroll` with `'#'` / `'#!'` guard
- `gamePopup` with DOM-presence guard

## Out of Scope (Tracked for Follow-up)

- jsdom unit tests for individual widgets (typewriter, carousel boundary wrap, tilt no-op under reduced motion, FAQ sibling-close, popup sessionStorage gate)

- A `scripts/check-page-widget-usage.js` to ensure no future page reintroduces widget code outside `TMPage`
